# 第二版 4B 与榜单前排的差距分析（2026-11-04）

## 对比对象和计算方法

- **我们**：`chinese-decision-pointer-4b-final`，开去偏，公开指数 53.40。
- **对比对象**：公开指数前 5 的 4B 模型，平均约 65.6 分：
  - StartLux 67.81
  - Senova 66.87
  - KnowLine 66.76
  - Jeffan 64.85
  - OneJev 61.95
- **数据**：每个模型的逐项 skill（机会校正后的分数）来自榜单 `data/index.json`。

"损失"表示一项差距让我们的指数少了多少分：

```
损失 = (前 5 平均 skill − 我们的 skill) × 领域权重 ÷ 领域内项目数
```

领域权重：知识 25.8%、语言 25.8%、检索 20%、工具 18.3%、艺术 10%。按这个算法，所有项目的损失加起来约 12.6 分，正好是我们和前 5 平均的差距。

### 三个结论

1. **训练塌缩**：RAGTruth 和 ESCI 合计损失 3.4 分，占总差距的 27%。这两项都有训练数据，问题出在训练稳定性和存档选择上，不是缺数据。
   - 塌缩发生在第 1,000 步到第 1,500 步之间。
   - 最后一步在 RAGTruth 上 98% 判"有幻觉"，在 ESCI 上 99% 选 S。
   - 我们自己的验证集其实已经看出来了：ESCI 准确率 17%，检索领域 32.7%。但验证集太小（RAGTruth 只有 18 条），而且没有按来源逐步记录，所以当时没发现。
2. **没有训练数据的题型**：CLadder、POP909、ACOS、VAST、MuSR、Habermas、SATA、ChessBench，合计损失约 5.1 分。
3. **已下载但没进混合数据的来源**：共 15 个。
   - Home-Assistant-Requests
   - New-Yorker-Caption-Contest
   - FEVER
   - MultiWOZ、CrossWOZ
   - Mind2Web
   - T2Ranking、MS-MARCO
   - FinQA、TAT-QA
   - MBPP、CodeContests
   - DeepMind-Mathematics
   - Phishing-Pot、SpaPhish

## 2. 正式分要注意的地方

正式分里，私有测试占 80%：同技能 60%，新领域 40%。前排模型从公开分到正式分都掉得很多：

| 模型 | 公开分 | 正式分 | 新领域 |
|---|---:|---:|---:|
| StartLux | 67.8 | 54.8 | 38.1 |
| Senova | 66.9 | 51.0 | 33.9 |
| KnowLine | 66.8 | 56.0（掉得最少） | |

KnowLine 的做法是自建"同技能"和"新领域"两类留出集，用它们来挑模型。所以补数据时：
- 要按题型补，不要照着公开题的措辞去拟合；
- 挑存档时，要看自己的留出集，不能只看公开分。

## 3. 策略和数据计划（按投入产出排序）

### A. 训练稳定性和存档选择（不用加数据，目标约 +2～3 分）

1. **加大验证集，并逐步记录每个来源的指标**：
   - 每个和榜单对齐的来源至少 200 题，各个标签均衡；
   - 每次验证都把按来源的指标写进日志和 SwanLab；
   - 按"各来源平均"来选最好的存档，不再只看总体 NLL。
2. **权重平均**：
   - 可以平均多个存档，比如第 600 步和最后一步，或者每 100 步一个存档做 EMA；
   - 也可以平均多次训练的结果，StartLux 就平均了 4 次训练。
3. **查清 ESCI 为什么塌缩**：
   - 先看 ESCI 训练数据里 E/S/C/I 各占多少，以及训练后期的 batch 里检索类数据的比例；
   - 再看有没有别的来源（JevEmbed、tasksource 的相关性题）在类似格式下给出了冲突的标签；
   - 必要时给 ESCI 加标签平衡（`balance`）。
4. **学习率退火到 0**：退火阶段换成分布均匀的数据，避免最后几百步被某些来源带偏。

### B. 补没有覆盖的题型（目标约 +3～4 分，损失大的放前面）

| 题型 | 来源 | 说明 |
|---|---|---|
| CLadder 因果推理 | **Corr2Cause**（有约 20 万条训练集）；或者用 CLadder 开源的生成器，换因果图和故事、用新的随机种子自己生成 | 生成后和测试集去重 |
| POP909 音乐 | 其他带和弦标注的 MIDI 数据，比如 Nottingham、Hooktheory、Lakh 带和弦的子集，按 POP909-CL 的题型生成 | 先看清楚官方的题目格式 |
| Home appliances | **已下载的 Home-Assistant-Requests**，再加自己生成的家居场景 | 写适配器就行 |
| ACOS | ACOS 训练集、SemEval-14/15/16 ABSA、ASTE | 和测试集去重 |
| VAST 立场 | VAST 训练集、SemEval-2016 Task 6、P-Stance；中文用 NLPCC-2016 立场数据 | |
| MuSR | 用 MuSR 开源的生成流程，加上 156 上的 Qwen3.6-27B 生成新的推理故事 | 开销较大，可以放后面 |
| API-Bank | API-Bank 的 level-1 训练集、xLAM-function-calling-60k、Glaive；ToolACE 也可以多用 | |
| Habermas | Habermas Machine 数据中不在测试集里的部分 | 需要确认许可 |

| GSM8K、BBH | 已下载的 DeepMind-Mathematics、MBPP、CodeContests，以及 MetaMathQA 等，转成选择题 | |

### C. 蒸馏（可选）

Perplexity Decider 的做法是用自家 27B 模型给题目打出完整的概率分布，再拿来训练小模型。我们可以用 156 上的 Qwen3.6-27B，给补充题型和没有标注的状态打软标签。这一步不使用 Jev 的输出。

### D. 训练流程

参照 StartLux 的两阶段做法：
- **第一阶段**：用现有的 210 万行；
- **第二阶段**：用 B 部分的新数据，加 30% 的第一阶段数据回放，学习率减半，逐来源验证；
- **结束后**：做权重平均，按自建的同技能和新领域留出集选存档。
