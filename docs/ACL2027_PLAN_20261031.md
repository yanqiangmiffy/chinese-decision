# ACL 2027 投稿评估、UIE 提升方案与执行计划

日期：2026-10-31。本文在 [10 月 27 日的方向调研](RESEARCH_DIRECTIONS_20261027.md) 基础上，加入已完成的 unified 4B 结果，重点回答三个问题：能不能投、性能够不够、UIE 怎么提。本轮读了代码、模型卡和公开文献，没有新跑模型；下文的“预期收益”都是待验证的假设。

## 一句话结论

- **能投，但不能按现在的形态投主会。** 现在的论文是“模型家族 + 工程 + 统一读出”的技术报告。它的每个组成部分在近邻工作里都已经出现过（Chinese-Jev、Jeva、GLiNER2、CalOn），外部基线也没有在同等条件下复现。审稿人大概率会给出“工程扎实、新意不足”的评价。
- **决策侧够强，抽取侧不够。** 4B 在 CJ-Bench 上达到 86.86%，是自己这条线上最好的结果。CJ-IE 抽取的 micro F1 是 68.9，**召回率只有 61.1%**；在标准数据集上比 BERT 时代的专项模型低 5 到 13 个点。
- **建议的主线：** 把已经观察到的“retention tax”做成一个受控、可证伪的科学问题。现象是：保持决策能力的联合训练让抽取掉 5 到 10 个 F1，35 个来源全部变差。研究问题是一个紧凑骨干同时承担概率决策和跨度抽取时，干扰从哪里来、怎样消除。同时用下面的 UIE 改进把抽取补到有竞争力的水平。
- **时间：** ARR 截止 **2027-01-04 23:59 AoE**（北京时间 1 月 5 日 19:59），从今天算约 9 周。4B 训练一次要 82 小时，只够跑一次 4B，最晚 12 月初必须开跑。
- **备选：** 到 11 月 21 日，如果 0.8B 受控实验仍然解释不了 retention tax，就转投 Findings 风格的严谨分析，或者转投 System Demonstrations（Decision Studio 加统一模型）。

## 一、现在的性能放在哪个位置

### 决策（CJ-Bench 全量，307,900 条，T = 1）

| 模型 | 整体 ACC | 四领域 macro |
|---|---:|---:|
| unified 0.8B | 83.46 | 76.17 |
| unified 2B | 85.00 | 79.12 |
| decision-only 4B | 85.97 | 81.92 |
| **unified 4B** | **86.86** | **83.85** |

联合训练没有损害决策能力，4B 甚至略好于纯决策版。这一点可以写进论文，但需要同步数、同数据预算的对照，才能说是联合训练带来的好处。

弱点仍然在：`score` 题型只有 61.6%；法律和金融的 ECE 不如纯决策 4B；外部基线是论文里报告的数字，不是在同条件下复现的。

### 抽取（CJ-IE test，精确匹配）

| | P | R | F1 |
|---|---:|---:|---:|
| unified 4B micro | 78.9 | **61.1** | 68.9 |
| 只训 CJ-IE 的 0.8B（遗忘版 v1，CJ-Bench 71.0） | — | — | 73.9 |
| unified 0.8B | — | — | 63.1 |

和公开结果的粗略对照如下。口径不同：CJ-IE 把类型统一成了 B2NERD 风格的标签，划分也不同，所以不能直接比。但审稿人一定会这样比。

| 数据集 | unified 4B（P / R / F1） | 公开专项模型参考 F1 |
|---|---|---|
| MSRA | 93.9 / **73.8** / 82.6 | 约 95.5 到 96.7（BERT 类；YAYI-UIE 报告 95.6） |
| Resume | 93.7 / 88.3 / 90.9 | 约 96 到 97.5 |
| Weibo | 77.1 / **54.1** / 63.6 | 约 69 到 72 |
| CLUENER（官方 dev） | 70.7 | 只用 4k 句训练的专项模型就有 78.7 |
| CMeIE（关系） | 64.1 / **24.4** / 35.4 | 明显偏低 |

**关键观察：几乎所有来源都是精确率远高于召回率。** MSRA 的精确率 93.9，召回率只有 73.8。这说明模型不是“认不出”实体，而是“不敢报”。这类问题通常有便宜的修法（见第三节 Tier 0）。

## 二、投 ACL 2027 的不足（审稿人视角）

| 不足 | 为什么致命 | 补法 |
|---|---|---|
| 新颖性 | 单前向读字母概率、统一分类加抽取、类型定义条件抽取、回显表示，都有直接前作（AnyJev、Jeva、GLiNER2、CalOn、Echo Embeddings / Just Pass Twice） | 不再以“我们做了一个统一模型”为贡献，改为回答一个具体的科学问题（第四节） |
| 基线 | 没有同条件复现 GLiNER2、B2NER、YAYI-UIE / IEPile、BERT-GlobalPointer 专项模型 | 至少在 MSRA / Weibo / Resume / OntoNotes4 / CMeEE / DuIE 的**原始标签体系**上补齐 |
| 抽取绝对水平 | 比专项模型低 5 到 13 F1，会被看作“统一的代价太大” | 第三节的 UIE 改进；同时把卖点定位成“一份权重、多套 schema” |
| 混淆因素 | retention tax 的对照（v1 和 v3）同时改了回放、KL、RLCD、累积步数 | 在 0.8B 上做一次只改一个因素的受控实验 |
| 泛化主张 | 测试时用的都是训练里见过的类型定义；`military_ner` 没有定义，F1 只有 3.0 | 留出来源 / 类型族，测未见定义 |
| 统计 | 单种子 | 0.8B 关键配置跑 3 个种子，做按来源成组的 bootstrap |
| 格式 | paper/v4 是自定义排版的技术报告 | 改写成 ACL 模板、匿名、8 页加 Limitations，并填 Responsible NLP checklist |
| 匿名性 | arXiv 2610.23170 已公开且署名 | 按 ARR 现行预印本政策处理（投稿前再核对一次），正文避免自我暴露 |

## 三、UIE 提升方案（按成本排序）

先说清楚现在的机制，因为它决定了修法：

- 跨度头对每个候选跨度（最长 20 字）在 [none, 类型…] 上做 softmax（[decision/modeling.py](../decision/modeling.py) `SpanHead`）。
- 训练时 none 跨度的权重为 0.2。推理时在 none 的 logit 上加回 `none_shift = log(1/0.2) ≈ +1.61`（[decision/losses.py](../decision/losses.py) `SpanLoss`），然后取 argmax，再贪心去掉重叠跨度（[decision/processing.py](../decision/processing.py) `decode_spans`, `flat=True`）。
- 这个 +1.61 的作用是恢复**校准**，它不是按 F1 选的操作点。`--thresholds` 只能让模型更保守，不能放宽。仓库里从来没有在开发集上扫过 `none_shift`。

### Tier 0：不训练，1 到 3 天，先做

| # | 做法 | 预期 | 怎么验证 |
|---|---|---|---|
| 0.1 | **在 CJ-IE dev 上扫 `none_shift`**（例如 +1.61、+1.0、+0.5、0、−0.5），选全局最优；再试按来源 / 按类型选 | 召回率最有可能大幅回升；这是最便宜的修法 | 在 dev 上选，只在 test 报一次；结果写进 `decision_config.json` 的 extraction 段（与校准用的 shift 分开存） |
| 0.2 | 嵌套解码：对 CMeEE 等允许嵌套的来源用 `flat=False`，或改成“同类型不重叠、跨类型允许重叠” | CMeEE 召回率 52.4 有提升空间 | 按来源分别报告 |
| 0.3 | **漏召回分解**：FN 里有多少是边界差 1 到 2 字、类型混淆、整句截断或超宽、完全没打分 | 决定 Tier 1 先做哪一项 | 用现有 span dump（`paper/v4/analysis/dump_spans.py`）离线统计 |
| 0.4 | 检查长文本：MSRA / Weibo 测试句是否被截断，是否超过训练时的 300 字窗口；必要时做重叠滑窗 | MSRA 召回率 73.8 偏低，可能有一部分来自这里 | 按长度分桶统计召回率 |
| 0.5 | 给没有定义的类型（military_ner）写定义；对弱类型试 2 到 3 种定义写法 | 衡量定义敏感度，这本身也是论文里的一项分析 | 固定权重，只改提示 |

> **0.1 已完成（2026-10-31）。** 详见 [none_shift 扫描报告](NONE_SHIFT_SWEEP.md)。在 dev 上选出 shift ≈ 0.75 后，test micro F1 分别为：0.8B 63.1 升到 64.6，2B 65.9 升到 67.3，4B 68.8 升到 70.6；召回率提升 6 到 9 个点。按来源分别选 shift、改用嵌套解码，都没有额外收益。结论是操作点只能解释和专项模型差距中的 1.5 到 2 个点（4B 的 MSRA 调完是 86.7，专项约 95.5），剩下的差距要靠 Tier 1 的训练改进。
>
> 0.1 的结论要单独写进论文：校准用的 none 校正和 F1 最优操作点不是一回事。两者分开报告，同时给出实体级 ECE，避免审稿人认为是“调阈值刷分”。

### Tier 1：0.8B 上的低成本训练对照（每次约 3 到 6 小时）

| # | 方法 | 依据 | 针对的问题 |
|---|---|---|---|
| 1.1 | **按任务切换注意力掩码**：抽取行在顶部 k 层（试 k = 4 / 8 / 全部）去掉因果掩码，决策行保持因果 | Looking Right is Sometimes Right（Findings ACL 2024）：去掉顶层因果掩码能明显提升 NER；LS-BiLLMs | 回显只是近似的双向表示；去掉掩码可能让回显变得不必要，同时缩短输入、加快推理 |
| 1.2 | **任务专属 LoRA**：共享骨干，决策 LoRA 加抽取 LoRA，按请求选择（发布时仍是一个文件，按请求路由） | 多任务干扰与 LoRA 合并文献（TIES / DARE、正交子空间 LoRA） | 直接针对 retention tax |
| 1.3 | 梯度冲突处理：PCGrad / CAGrad，或对决策 KL 锚和抽取损失做动态加权 | 多任务优化 | retention tax 的另一种解释：梯度冲突，而不是容量不足 |
| 1.4 | **两阶段读出**：先做“是不是实体”的二分类过滤（阈值在 dev 上选），再做类型分类；或者降低 none 权重（0.2 降到 0.1），也可以换成 focal loss | NER as Structured Span Prediction（2022）；GLiNER 关于负例比例的消融 | 精确率高、召回率低的结构性原因 |
| 1.5 | 边界辅助损失：加起止位置头（GlobalPointer / biaffine 风格），或者给边界附近的跨度软标签 | GlobalPointer 类方法 | 0.3 里如果边界错误占大头，就做这一项 |
| 1.6 | LoRA 秩：r = 32 提到 64 / 128，或对抽取行加 MLP 模块 | 容量假设 | 区分“容量不足”和“干扰” |
| 1.7 | 数据配比：对 Weibo、MultiCoNER2、CMeIE、CLUENER 做温度采样上采样；对 schema 里出现但文本中没有的类型做负类型训练 | B2NER / IEPile 的数据经验 | 弱来源 |
| 1.8 | CMeIE 关系重新建模：检查召回率 24.4 是不是因为“一次请求多关系”或主语条件化方式的问题 | 召回率异常低，先查任务构造 | CMeIE |
| 1.9 | 定义增强：对类型说明做改写、同义扰动，并合成新类型 | GUIDEX、B2NER | 未见类型的泛化 |

每个对照都要记录三件事：CJ dev 决策准确率（不能比基线低超过 0.3）、CJ-IE dev F1、吞吐。

### Tier 2：有余力再做

- 用大模型（例如 Qwen3.5-9B 加少量样本，或现有外部 UIE 模型）在无标注中文文本上做伪标注和自训练，主要针对召回率。
- 合并路线：分别训练决策专家和抽取专家，再用 TIES / DARE 合并，和联合训练对比。这本身就是 retention tax 论文里的一条基线。

## 四、建议的论文主线

**暂定题目：** *The Retention Tax: Decision–Extraction Interference in Compact Unified Language Models*（中文：紧凑统一模型中决策与抽取的相互干扰）

**核心问题：** 一个 0.8B 到 4B 的骨干同时承担单前向概率决策和类型化跨度抽取。为了保住决策能力（回放加 KL 锚），抽取要付多少代价？这个代价来自哪里：容量不足、梯度冲突、注意力形态不匹配，还是解码操作点？能不能在不损失决策能力的前提下收回？

**为什么比 10 月 27 日的方向 A 更适合这一轮：** 方向 A 要新标注约 300 个母文本的干预数据，9 周内风险很高。这条主线需要的现象已经观察到，35 个来源全部同方向；数据、代码和三个尺寸的模型都已就绪；每个假设都对应一个可以证伪的对照实验。

**可能的贡献（以实验结果为准，不预设）：**

1. 受控测量：在同数据、同步数下，单独改回放、KL、RLCD、LoRA 秩、注意力掩码，量化每个因素对 retention tax 的贡献，跨 0.8B / 2B / 4B 三个尺寸。
2. 一个简单有效的修法：最可能的候选是 1.1（任务条件化的双向注意力）或 1.2（任务专属 LoRA），配合 0.1（校准和 F1 操作点分开）。
3. 在原始标签体系上和 GLiNER2、B2NER、YAYI-UIE、专项模型做同条件对比，并报告未见类型的泛化。

**否定条件：**

- 如果在 0.8B 上发现 retention tax 主要由 `none_shift` 操作点解释（Tier 0 就收回了大部分差距），主线就改成“校准与操作点”的分析短文，或者并入 Findings。
- 如果所有方法都收不回差距，就把它写成一个有边界的负结果分析（ACL 2027 CFP 接受负结果）。
