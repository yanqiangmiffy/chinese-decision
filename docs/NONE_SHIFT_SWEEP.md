# 抽取操作点（none_shift）扫描

日期：2026-10-31。脚本：[scripts/sweep_none_shift.py](../scripts/sweep_none_shift.py)。运行环境：服务器 156，GPU 2、3、4，每个尺寸一张卡。数据：CJ-IE（35 个来源，dev 11,647 行，test 85,041 行）。模型：`runs/cj-ie-{0.8b,2b,4b}-from-base/model`，即发布的 unified 模型。

做法：每行只做一次前向，然后用 9 个 `none_shift` 取值 × {flat 解码、嵌套解码} 分别解码。**只在 dev 上选设置**，再在 test 上报一次。发布模型的设置是 `none_shift = log 5 ≈ 1.609`、flat 解码。原始结果在 `reports/none-shift-sweep-20261031/sweep_*.json`（未纳入版本库）。

## 结果（test，精确匹配，micro）

| 模型 | 设置 | P | R | F1 | 来源宏平均 F1 |
|---|---|---:|---:|---:|---:|
| 0.8B | 发布（1.609） | 73.3 | 55.4 | 63.1 | 62.4 |
| 0.8B | dev 选出：0.5，flat | 64.8 | 64.4 | **64.6**（+1.5） | **65.1**（+2.7） |
| 2B | 发布（1.609） | 75.4 | 58.6 | 65.9 | 66.3 |
| 2B | dev 选出：1.0，flat | 70.6 | 64.3 | **67.3**（+1.4） | **68.0**（+1.7） |
| 4B | 发布（1.609） | 79.0 | 61.0 | 68.8 | 69.7 |
| 4B | dev 选出：0.75，flat | 72.5 | 68.7 | **70.6**（+1.8） | **71.6**（+1.9） |

发布设置那一行的数字与模型卡一致（63.1 / 66.0 / 68.9，差别只在四舍五入），说明评测口径对得上。

## 结论

1. **调操作点稳定有效，但增益不大。** 三个尺寸都提升了 1.4 到 1.8 micro F1、1.7 到 2.7 宏平均 F1。召回率提升 6 到 9 个点，精确率下降 5 到 8 个点。
2. **最优点很平。** dev 上 shift 在 0.5 到 1.0 之间时，F1 相差不到 0.3。建议所有尺寸统一用 **0.75**，不需要按尺寸分别调。
3. **按来源分别选 shift 不值得。** micro F1 不升反降（0.8B 是 64.1 对 64.6，4B 持平），宏平均只多 0.5 到 0.7。来源的 dev 集太小，按来源选会过拟合。
4. **嵌套解码整体无益。** 在各自最优的 shift 下，嵌套解码都比 flat 低 0.3 到 0.6。少数来源（如 CMeEE）在 dev 上选中了嵌套，但不值得为此做全局改动。
5. **增益最大的来源**（4B）：CMeIE +7.4（召回 24.3 升到 35.2）、CCKS2017 +6.8、Boson +5.2、CAIL2021 +4.1、MSRA +4.0（82.7 升到 86.7）、FNED +4.0、FewFC +3.1、MultiCoNER2 +3.0。**变差的来源**：WikiANN −1.2、NLPCC2018 −1.0、MultiNERD −0.6、OntoNotes −0.4、DuIE −0.1。这几个来源本来精确率和召回率就比较均衡。
6. **和 BERT 的差距大部分不是操作点造成的。** 调完之后，MSRA 是 86.7，仍比专项模型（约 95.5）低约 9 个点；Weibo 64.0，专项约 69 到 72；Resume 91.6，专项约 96。剩下的差距要靠训练改进（ACL 计划里的 Tier 1）。
7. **retention tax 不能用操作点来解释，但还没有严格确认。** 只训 CJ-IE 的 v1 模型（73.9）没有一起扫描。要严格比较，需要把 v1 也用同样的方法扫一遍。

## 注意：概率与决策门槛要分开

`decode_spans` 输出的实体概率，是加了 shift 之后的 softmax。把 shift 改成 0.75，选出的实体变了，**报告的概率也会变**，不再对应训练时校准好的那个值。建议的发布方式：

- 实体概率仍按校准用的 1.609 计算，保持可信；
- 是否输出某个实体，用 F1 最优的 0.75 来判断。

这需要在 `decision_config.json` 的 extraction 段新增一个与 `none_shift` 分开的“决策 shift”字段，并修改 `decode_spans`。已完成，见下一节。

## 更新：判定阈值与校准概率已拆开（2026-10-31）

拆开的方式：

- `decision_config.json` 的 extraction 段新增 `decision_shift`。它只决定哪些跨度算实体；输出的概率仍按 `none_shift` 计算，保持校准。
- 不写这个字段，或把它设成 `None`，就和原来的行为完全一样。
- 三个 unified 模型都已写入 `decision_shift = 0.75`：服务器 156 的 `runs/cj-ie-*-from-base/model/`，以及本地的 `models/chinese-decision-unified-*`。原配置备份为 `decision_config.json.bak-20261031`。

用默认推理路径（`predict_spans`，不传任何 shift）在 CJ-IE test 上验证，35 个来源合并计算：

| 模型 | 发布行为 P / R / F1 | 新默认 P / R / F1 | 实体 ECE（发布 → 新） |
|---|---|---|---|
| 0.8B | 73.3 / 55.4 / 63.1 | 66.7 / 62.8 / **64.7** | 4.2% → 4.0% |
| 2B | 75.4 / 58.6 / 65.9 | 68.6 / 66.0 / **67.3** | 1.8% → 2.3% |
| 4B | 79.0 / 61.0 / 68.8 | 72.5 / 68.7 / **70.6** | 3.2% → 4.2% |

F1 与扫描结果一致。实体 ECE 只在模型输出的实体上计算。新放进来的实体置信度较低，所以 2B 和 4B 的 ECE 略有上升，但仍在 2% 到 4% 之间。
