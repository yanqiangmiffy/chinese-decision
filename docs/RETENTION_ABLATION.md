# retention tax 受控实验（0.8B）

日期：2026-11-01。**本文在看到任何结果之前写成**：配置、预测、读结果的规则都先定好，跑完只往“结果”一节里填数字，不改前面的内容。背景见 [RESEARCH_BRAINSTORM_20261101.md](RESEARCH_BRAINSTORM_20261101.md) 第二节。

## 要回答的问题

unified 0.8B 在 CJ-IE test 上，比只训 CJ-IE 的 v1 低 9.5 个 micro F1。两者都已经调到各自最优的判定阈值，所以这不是阈值造成的。但两者在好几个地方同时不同：

| | v1 | unified 0.8B |
|---|---|---|
| 起点 | chinese-decision-0.8b（已经训过决策） | 原始 Qwen3.5-0.8B |
| 回放 | 无 | 1,305 万条 CJ 决策数据（约 11 倍于 CJ-IE） |
| KL 锚 | 不适用 | 关闭（`--kl-weight 0`） |
| 训练目标 | CE | CE + RLCD |
| 批次 | 16 / 8 行，12k token，4 卡，不累积 | 32 / 16 行，24k token，4 卡 × 8 次累积 |

还有一处代码上的事实：LoRA 的梯度是对所有任务的 micro-batch 取平均（`sync_gradients`），跨度头只对抽取的 micro-batch 取平均。所以回放越多，抽取在共享 LoRA 更新里所占的分量就越小。

## 实验协议（所有配置相同）

- **数据：** 每个抽取来源均匀抽 8,000 行（共 198,100 行），IE 决策题均匀抽 200,000 行。有回放的配置，从 CJ-full train 均匀抽 1,200,000 行，约为 IE 数据的 3 倍。抽样用 `--max-lines` 和 `--seed 42`，所有配置抽到的行完全相同。
- **训练：** 单卡；决策 32 行 / 抽取 16 行；每个 micro-batch 最多 24,576 token；累积 2 次。这样每次更新的行数和 v1（4 卡 × 16 / 8 行）一样。LoRA r = 32，lr 1e-4，跨度头 lr 5e-4，预热 100 步，1 个 epoch。除非该配置要改的正是这一项。
- **选模型：** 一律取最后一步（`--selection last`），不按开发集挑选。
- **评测：**
  1. 抽取：用 [sweep_none_shift.py](../scripts/sweep_none_shift.py) 在 CJ-IE dev 上选判定阈值，CJ-IE test 只报一次 micro F1 和来源宏平均 F1；
  2. 决策：CJ dev 准确率（3,600 条，与 CJ-Bench 无关）和 IE 决策题的 dev 准确率；
  3. 记录训练耗时。
- **种子：** 这一轮每个配置跑 1 个种子，用于筛选。被选中的修复办法再补 2 个种子。

## 配置和预测

U 是“缩小版 unified”：原始底座、回放、RLCD。其余配置都只在 U 的基础上改一处（C7 和 C8 除外，原因见下表）。

| 编号 | 配置 | 相对 U 改了什么 | 检验的假设 | 预测 |
|---|---|---|---|---|
| U | 原始底座 + 回放 + RLCD | — | 参照 | 抽取 F1 低于 C1 |
| C1 | 原始底座，无回放 | 去掉回放 | H1：回放本身造成代价 | 抽取 F1 明显高于 U；决策准确率明显低于 U |
| C2 | 决策模型起点 + 回放 | 起点换成 chinese-decision-0.8b | H2：起点造成差距 | 如果 H2 成立：抽取 F1 明显高于 U |
| C3 | 决策模型起点，无回放 | 同时换起点、去掉回放（与 C1、C2 组成 2×2） | 两者的交互作用 | 最接近 v1 |
| C4 | U + CE | 关掉 RLCD | H3：RLCD 造成代价 | 抽取 F1 与 U 相差在 1 以内（预测 H3 不成立） |
| C5 | U + 抽取损失权重 4 | `--extraction-weight 4`（≈ 1 + 回放倍数） | H4：稀释，抽取在 LoRA 更新中的分量被回放冲淡 | 如果 H4 成立：收回 U 和 C1 之间一半以上的差距，决策准确率下降不超过 0.5 |
| C6 | U + LoRA r = 128 | 容量 | H5：容量不足 | 如果 H5 成立：收回一半以上的差距 |
| C7 | 决策模型起点 + 回放 + KL 锚 | 在 C2 上开 `--kl-weight 1` | H6：KL 锚让抽取变保守 | 与 C2 相比，抽取 F1 降低、召回率降低 |

## 读结果的规则

记 **差距 = C1 的抽取 F1 − U 的抽取 F1**（都在最优阈值下，取 test 上的 micro F1）。

1. **如果差距小于 2 个点：** 在这个规模下复现不出 retention tax。先检查是不是回放比例（3 倍对 11 倍）太小，必要时把 U 和 C1 的回放加到 6 倍以上重跑，再继续讨论修复办法。
2. **如果 C2 的抽取 F1 − U 的抽取 F1 ≥ 差距的一半：** 起点是主因。论文主线要改写成“统一训练应该从哪个起点出发”，而不是“保住决策能力的代价”。
3. **如果 C5 或 C6 收回了至少一半差距，而且决策准确率（CJ dev）下降不超过 0.5：** 这个修复就是候选办法，补 2 个种子之后放到全量上确认。
4. **如果 C4 和 U 的差别超过 2 个点：** RLCD 对抽取有影响，要单独分析。
5. **单种子的差别小于 1 个点时，一律视为没有差别。**
